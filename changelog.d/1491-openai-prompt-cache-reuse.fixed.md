OpenAI-backend generations now reuse the provider prompt cache instead of rewriting their ~60–78K-token prefix at full price on every attempt (axiom-encode#1491, `cached_tokens=0` across all campaign traces). Two changes: the per-attempt validation-retry feedback section moved from the middle of the authoring prompt to its tail, directly above the rejected candidate it describes, so retry prompts extend a byte-identical static prefix rather than splitting it; and Responses API requests carry a `prompt_cache_key` derived from the prompt head, routing retries and near-in-time redispatches of the same citation to the cache shard holding the entry. Cache reads were already surfaced per attempt (`cache_read=`), so the effect is visible in every CI log line.
